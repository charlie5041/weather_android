# 出行看天氣：功能與 UI/UX 改版提案

> 目標：讓「要出門的人」一眼看懂**這趟路上**會遇到什麼天氣，而不只是看某個城市的天氣。

---

## 一、市面上的同類 App 做了什麼

| App | 平台 | 特色功能 | 本 App 是否已有 |
| --- | --- | --- | --- |
| **Weather on the Way** | iOS | 依經過時間算沿路天氣；可選 7 天內的出發時間；**比較多條路線**；能見度、風、UV；**沿路天氣特報**、路況攝影機；CarPlay | 部分（無多路線、無多日、無特報疊加、無攝影機） |
| **Drive Weather** | iOS / Android | **出發時間滑桿**，拖動即時看沿路變化；依自己的車速微調；離線時每 30 分鐘更新；CarPlay | 部分（只有固定的幾個時間按鈕） |
| **Wayther (Highway Weather)** | iOS | 一次給 **3 條路線**比較；可**依抵達時間**規劃；10 天內；能見度與路面狀況；路線摘要＋時間軸 | 無多路線、無「指定抵達時間」 |
| **ArriveDry** | iOS | 在**背景監看路線**，雨快打到路上時推播（App 沒開也會）；路線上疊**雷達**；依天氣排序替代路線；Live Activity | 無背景監看、無雷達 |
| **Along / Commuter Weather** | iOS | 沿實際通勤路線取樣；官方警特報；出門前「帶傘」提醒 | 已有（通勤卡片＋帶傘提醒） |
| **REVER**（機車族） | iOS / Android | 路線規劃＋雷達、風、對流胞、閃電圖層；CarPlay | 無圖層 |
| **Route Cast** | iOS | 機車／敞篷車用，**強側風**、冰雹警示 | 無風的警示 |
| **AccuWeather** | 多平台 | 沿路線預報＋**建議最佳出發時間** | 已有（「改成 hh:mm 出發」） |
| **中央氣象署 Q** | iOS / Android | 雷達回波、**未來 1 小時雨區預報**、即時閃電；可設**依 GPS 移動的雨量門檻提醒** | 無 |
| **觀天氣、OwlWeather** | iOS / Android | 每 10 分鐘的雨勢變化、未來 1 小時雨量（台灣） | 無短時（分鐘級）預報 |

**本 App 已經比較強的地方**：台灣在地資料（氣象署鄉鎮預報＋雨量站實測）、機車模式與機車速度、Google 地圖分享路線進來、通勤卡片、依鄉鎮合併沿途清單。這些是國外 App 做不好的，應該當作主打。

## 二、你可能沒想到的功能（依優先順序）

### P0：用現有資料就能做，效益最高

1. **不只看雨：沿路風、體感、UV、天黑**
   `HourlyForecast` 已經有 `windGusts`、`apparentTemperature`、`uvIndex`、`isDay`，但路線畫面只用了降雨。
   - 機車／腳踏車：陣風 ≥ 50 km/h 提示「橋上、海邊注意側風」（Route Cast 的賣點）
   - 機車：車速造成的風寒，冬天顯示「騎乘體感約 9°」
   - 步行／腳踏車：UV ≥ 8 提醒防曬；體感 ≥ 36° 提醒中暑
   - 「17:42 日落，後半段會天黑」——長程機車很需要
2. **沿路天氣特報**
   已經抓了特報（W-C0033），把路線經過的縣市和特報區域比對：「沿途苗栗縣、台中市有大雨特報」，放在結論最上面。
3. **出發時間比較條**（取代現在的幾個固定按鈕）
   `RoutePlanner.evaluate` 已經在算 +30／60／90／120 分鐘的風險，直接把結果畫成一排：
   ```
   現在  +30m  +1h  +1.5h  +2h  +3h
   70%   65%   30%   20%   20%  40%
   ███   ███   ▅▅▅   ▂▂▂   ▂▂▂  ▅▅▅
   ```
   點一欄就換出發時間。這就是 Drive Weather 的「時間滑桿」，但更適合單手操作。
4. **常用路線（不只記上一條）＋每條各自的提醒**
   例如「週六早上 7 點 台北→宜蘭（機車）」，出發前 1.5 小時推播沿路結論；跟現在的通勤提醒共用 `WeatherSyncWorker`。
5. **通勤卡片用真實行車時間**
   `CommuteTrip.arrival` 目前寫死 `departure.plusHours(1)`，可以改用上次查到的路線時間，並把沿路雨況直接畫成卡片上的一條色帶（見三、2）。

### P1：需要接新資料或 API

6. **雷達回波＋短時（0–1 小時）降雨預報疊在路線圖上**
   鄉鎮逐時預報對「30 分鐘後會不會淋到」不夠準；台灣使用者習慣看氣象署雷達。前 1 小時的點用雷達外延（nowcast），之後才用逐時預報，準確度會明顯提升。也是 ArriveDry、REVER、氣象署 Q 的核心。
7. **替代路線比較**
   Google Routes 有 `computeAlternativeRoutes`，OSRM 有 `alternatives=true`。顯示 2–3 條路線，各自標「最高降雨 30% · 52 分」，讓使用者選比較乾的（Weather on the Way、Wayther、ArriveDry 都有）。
8. **「要在幾點抵達」模式**＋**選日期**
   現在的時間選擇只能選時分（過了就當明天）；出遊常是「週六早上 9 點要到」。
9. **山區路線**：經過高海拔（例如合歡山、阿里山公路）時用氣象署的育樂／山區預報，或依海拔修正溫度（約每 100 m −0.6°C），提示起霧、低溫。
10. **沿路空氣品質**：已經有環境部 AQI，機車族在意。

### P2：差異化、成本較高

11. **騎乘中模式**：開始導航後以前景通知顯示「前方 15 分鐘（約 6 公里處）開始下雨」，依 GPS 位置更新剩下的路段（ArriveDry 的背景監看）。
12. **道路事件**：交通部 TDX 的道路阻斷、施工、即時 CCTV 影像（Weather on the Way 有美國 DOT 攝影機）。
13. **多日行程／環島**：一條路線分成數天，每天各自的出發時間。
14. **分享沿路天氣圖卡**：揪團騎車時傳到 LINE 群組。
15. **Android Auto**、**桌面小工具顯示下一趟常用路線**。

## 三、UI/UX 優化

以下依據目前程式碼（`RouteScreen.kt`、`WeatherApp.kt`、`CommuteCard.kt`）。

### 1. 主打功能藏太深
App 名稱是「出行看天氣」，但路線功能的入口只有底部列左邊一個**沒有文字的小圖示**（`BottomBar` 的 `RouteIcon`，也沒有 `contentDescription`）。第一次用的人很難發現。

建議：
- 天氣主頁最上方（或目前天氣下方）放一張**「出門」卡片**：有常用路線就顯示下一趟的沿路結論；沒有就顯示「要去哪？查沿路天氣」的輸入框，點了直接進終點搜尋。
- 底部列的路線按鈕加文字或改成明顯的膠囊按鈕「🛵 沿路天氣」。
- 畫面標題「路線降雨」改為「沿路天氣」，因為會加入風、溫度、天黑等資訊。

### 2. 結果頁：先給結論，再給細節
目前的順序是「灰色小字的時間與距離 → 一長句摘要 → 地圖 → 清單」，使用者要讀完一整句才知道會不會淋雨。

建議改成：

```
┌───────────────────────────────────┐
│  ☂️ 15:20 後可能下雨                 │ ← 大字結論（一句話，最多 12 字）
│  台中市區一帶 · 降雨機率 70%          │
│                                   │
│  ▁▁▁▁▁▁▁▁▃▃▅▅██████▅▃▁▁           │ ← 雨況時間軸（橫向色帶，寬度 = 行程時間）
│  14:30         15:20        16:10  │
│                                   │
│  ⚠ 苗栗縣大雨特報   💨 陣風 55 km/h │ ← 其他提醒（有才顯示）
│  🌇 17:42 日落                      │
├───────────────────────────────────┤
│  出發時間  現在 +30m +1h +1.5h +2h  │ ← 出發時間比較條（二、3）
│           70%  65%  30% ✓20%  20%  │
├───────────────────────────────────┤
│  [地圖]                             │
├───────────────────────────────────┤
│  沿途（依鄉鎮）                      │
└───────────────────────────────────┘
│ 52 公里 · 約 1 小時 40 分（含路況）    │ ← 距離、資料來源移到地圖下方
```

- **雨況時間軸**是整個改版最重要的元件：一條橫向色帶就能看出何時、多久會淋雨。同一個元件可以放在通勤卡片、桌面小工具與通知。
- 起終點與交通方式在有結果後**收合成一行**（「台北 → 新竹 · 🛵 · 現在出發」，點了展開編輯），把螢幕留給結果。

### 3. 顏色與圖例
- 起點圓點用 `RouteDry` 綠色，和「不太會下」同色，容易誤會。起終點改用 A／B 標記或白底圖釘。
- 綠／黃對色弱使用者不好分；色帶與清單除了顏色也加上**圖示或花紋**（☂ 個數、斜線），或改用單一藍色系由淺到深表示雨勢。
- 圖例字級 11sp 太小，且只要時間軸夠直覺就可以拿掉圖例。

### 4. 沿途清單
- 每一列的第二行塞了「距離 · 天氣描述 · 雨量」，常被截斷；建議只留**鄉鎮＋經過時間**，雨量放右側機率底下。
- 合併的鄉鎮列可以在左側直接畫出那一段的小色帶，不用展開也知道中間有沒有雨。
- 有風或低溫提醒的點，在右側加小圖示（💨、🥶）。

### 5. 互動細節
- `⇅`、「改成 hh:mm 出發 ›」、「顯示全部 N 個點」、模式膠囊等是 `Text.clickable`，觸控範圍小、讀屏軟體讀不到角色。改用 `IconButton` / `TextButton`（至少 48dp），加 `contentDescription` 與 `Role.Button`。
- 載入中只有一個轉圈；路線常需要數秒（要查 25–50 個點），建議先畫路線與骨架色帶，再逐段填入天氣。
- 錯誤訊息只有「請檢查網路連線」，應區分「找不到路線」與「天氣資料暫時無法取得」，並提供「重試」按鈕。
- 沒有輸入起終點時的空白畫面，改成顯示**常用路線與最近查過的路線**。
- 「完成」在左上角、標題置中、右邊留白——可以改成左上「✕」、右上放「分享」或「⭐ 加入常用路線」。

### 6. 通勤卡片
- 加入雨況時間軸，並顯示真實行車時間（不再固定 1 小時）。
- 「查看沿途降雨 ›」改成整張卡片可點。

## 四、開發順序與進度

> 六個階段都已實作（分支 `claude/beautiful-cerf-eegyqf`）。TDX 道路事件的 API 網址與欄位未能實際呼叫驗證；Android Auto 只用清單與面板範本。

| 階段 | 內容 | 主要修改檔案 |
| --- | --- | --- |
| 1 | 雨況時間軸元件＋結論大字＋出發時間比較條 | `RouteScreen.kt`、`Route.kt` |
| 2 | 沿路風／體感／UV／天黑提醒、沿路特報 | `Route.kt`（新增 `RouteHazard`）、`RouteScreen.kt` |
| 3 | 主頁「出門」卡片、底部入口、常用路線＋提醒 | `WeatherPage.kt`、`WeatherApp.kt`、`AppSettings.kt`、`WeatherSyncWorker.kt` |
| 4 | 替代路線、抵達時間模式、選日期 | `GoogleRoutes.kt`、`Route.kt`、`RouteScreen.kt` |
| 5 | 雷達疊圖與 0–1 小時短時預報 | 新的資料來源、`RouteScreen.kt` |
| 6 | 騎乘中模式、TDX 道路事件、Android Auto | 新模組 |
